# Общая картина системы

Эта страница объясняет, как устроен проект VibeHunt и этот репозиторий. Подробности в файлах, на которые ведут ссылки. Список файлов папки: [TOTL-00-00-00-0](TOTL-00-00-00-0%20-%20%D0%9E%D0%B1%D1%89%D0%B0%D1%8F%20%D0%BA%D0%B0%D1%80%D1%82%D0%B8%D0%BD%D0%B0%20%D1%81%D0%B8%D1%81%D1%82%D0%B5%D0%BC%D1%8B.md).

## Что делает сервис

VibeHunt это двусторонний SaaS для подбора. Компания получает отчёт о соответствии кандидата позиции по трём осям: справится, приживётся, сработается. Цель: не допустить ошибку найма, то есть уход в первые 3–6 месяцев. Кандидат получает собственный профиль.
Подробнее: [суть проекта](TOTL-02-00-00-0%20-%20%D0%A1%D1%83%D1%82%D1%8C%20%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D0%B0.md). Источник: `vh84/docs/processes.md`.

## Кто участвует

Три роли: HR, Кандидат, Админ (сервис). Подробнее: [роли в сервисе](TOTL-02-01-00-0%20-%20%D0%A0%D0%BE%D0%BB%D0%B8%20%D0%B2%20%D1%81%D0%B5%D1%80%D0%B2%D0%B8%D1%81%D0%B5.md).

## Как устроены продукты

Продукты делятся на две группы и лежат в одноимённых папках.

| Папка | Для кого | Что внутри |
|---|---|---|
| `B2B` | для компаний | `CULT` культурный код, `RECR` рекрутинг (RECR-01…06: vacancy, match, interview, predictive, offer, adaptation) |
| `B2C` | для сотрудников | `VIBE` создание профиля сотрудника (VIBE-01…04: карьерный трек, карьерный вайб, личный профиль, стиль коммуникации) |

Источник структуры: Максим, 03.10.2026. Обзоры лежат в `B2B/B2B-00-00-00-0` и `B2C/B2C-00-00-00-0`.

## Как продукты связаны с процессами

Сервис состоит из десяти процессов: от культурного кода компании до работы с кадровым резервом. Каждый процесс относится к одному или нескольким продуктам. Таблица соответствия и порядок процессов: [десять процессов сервиса](TOTL-02-02-00-0%20-%20%D0%94%D0%B5%D1%81%D1%8F%D1%82%D1%8C%20%D0%BF%D1%80%D0%BE%D1%86%D0%B5%D1%81%D1%81%D0%BE%D0%B2%20%D1%81%D0%B5%D1%80%D0%B2%D0%B8%D1%81%D0%B0.md). Соответствие предположение, не подтверждено.
Процесс 3 (профиль кандидата) разобран отдельно: [профиль кандидата](TOTL-02-02-03-0%20-%20%D0%9F%D1%80%D0%BE%D1%84%D0%B8%D0%BB%D1%8C%20%D0%BA%D0%B0%D0%BD%D0%B4%D0%B8%D0%B4%D0%B0%D1%82%D0%B0.md).

## Как устроен этот репозиторий

- `vh_SSOT` в git главный источник фактов проекта. Obsidian и Notion только копии, синхронизация из git в копии.
- Папки и имена файлов подчиняются правилам: [правила нейминга](TOTL-01-01-00-0%20-%20%D0%9F%D1%80%D0%B0%D0%B2%D0%B8%D0%BB%D0%B0%20%D0%BD%D0%B5%D0%B9%D0%BC%D0%B8%D0%BD%D0%B3%D0%B0.md).
- Откуда взяты факты и что не сверено: [источники и расхождения](TOTL-01-00-00-0%20-%20%D0%98%D1%81%D1%82%D0%BE%D1%87%D0%BD%D0%B8%D0%BA%D0%B8%20%D0%B8%20%D1%80%D0%B0%D1%81%D1%85%D0%BE%D0%B6%D0%B4%D0%B5%D0%BD%D0%B8%D1%8F.md).

Источник принципа: `context-handoff-2026-10.md`, раздел «Принцип».

## Где что хранится вне этого репозитория

Не описано здесь подробно, источник: `context-handoff-2026-10.md`.

| Место | Что хранит |
|---|---|
| Obsidian | чанки по понятиям со ссылкой на источник |
| Notion | рабочие данные людей: канбан, базы, описания скиллов |
| Google Drive | файлы вне git: записи встреч, таблицы, макеты. Из этого репозитория на них только ссылки |
| `vh_tech`, `vh_knowledge`, `vh_teams`, `vh_dashboard`, `vh_router` | соседние репозитории проекта: скрипты и скоринг, методологии и глоссарий, пространство агентов, дашборды, маршруты |
