# Общая картина системы VibeHunt

Начните здесь. Эта страница за несколько минут объясняет, что такое VibeHunt, из чего он состоит, что делаем первым и как читать этот репозиторий. Подробности в файлах по ссылкам.

## Что такое VibeHunt

Predictive talent platform: предиктивная платформа для работы с талантами. Обещание клиенту: точная диагностика командного вайба.
Покупатель: HRD компании. Платформа SaaS. Личный консультант отдельная платная услуга, продукт существует без неё.
Подробнее: [суть проекта](TOTL-02-00-00-0%20-%20%D0%A1%D1%83%D1%82%D1%8C%20%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D0%B0.md), [услуги и внедрение](TOTL-02-06-00-0%20-%20%D0%A3%D1%81%D0%BB%D1%83%D0%B3%D0%B8%20%D0%B8%20%D0%B2%D0%BD%D0%B5%D0%B4%D1%80%D0%B5%D0%BD%D0%B8%D0%B5.md).
Источник: презентация «VibeHunt для HRD», 30.09.2026; решение Максима, 03.10.2026.

## Три направления и старт MVP

| Направление | Результат для клиента | Дивизионы | В старте MVP |
|---|---|---|---|
| Повысить скорость и точность найма | найм по соответствию кандидата задачам, ценностям компании и руководителю | `RECR` рекрутинг, `CULT` культурный код, `VIBE` вайб сотрудника | да |
| Собрать сбалансированную команду | оцифровка динамики команды и план действий | `TEAM` | нет |
| Улучшить вовлечённость | вовлечённость через игровые механики и контроль своего состояния | `AIBOT`, `WAIBO` | нет |

Подробнее: [объём MVP](TOTL-02-07-00-0%20-%20%D0%9E%D0%B1%D1%8A%D1%91%D0%BC%20MVP.md).

## Как читать этот репозиторий

```
vh_SSOT/
├── TOTL/      общая картина системы (здесь)
├── B2B/       продукты для компаний: CULT, RECR, TEAM, AIBOT
└── B2C/       продукты для сотрудников: VIBE, WAIBO
```

- В каждой папке лежит обзор с кодом `-00-00-00-0`. Имена файлов подчиняются [правилам нейминга](TOTL-01-01-00-0%20-%20%D0%9F%D1%80%D0%B0%D0%B2%D0%B8%D0%BB%D0%B0%20%D0%BD%D0%B5%D0%B9%D0%BC%D0%B8%D0%BD%D0%B3%D0%B0.md).
- Список файлов этой папки: [TOTL-00-00-00-0](TOTL-00-00-00-0%20-%20%D0%9E%D0%B1%D1%89%D0%B0%D1%8F%20%D0%BA%D0%B0%D1%80%D1%82%D0%B8%D0%BD%D0%B0%20%D1%81%D0%B8%D1%81%D1%82%D0%B5%D0%BC%D1%8B.md).

## Правила для людей и агентов

- `vh_SSOT` в git главный источник фактов. Obsidian и Notion только копии, синхронизация из git в копии.
- Отвечай со ссылкой на источник. Если факта нет, говори «нет подтверждения». Если результат расходится с фактом, говори «противоречит».
- Статус файла в начале: `черновик` или `проверено`. Статус `проверено` ставит человек.
- Пометка «не подтверждено» значит предположение. Не опирайся на него как на факт.

Источник правил: `context-handoff-2026-10.md`.

## Что пока не решено

- Какой источник главнее для найма: `vh84/docs` или BRD/PRD/FRD v1.1 в `VibeHunt88`. См. [источники и расхождения](TOTL-01-00-00-0%20-%20%D0%98%D1%81%D1%82%D0%BE%D1%87%D0%BD%D0%B8%D0%BA%D0%B8%20%D0%B8%20%D1%80%D0%B0%D1%81%D1%85%D0%BE%D0%B6%D0%B4%D0%B5%D0%BD%D0%B8%D1%8F.md).
- Соответствие процессов продуктам: предположение.
- Рамка культурного кода: должна быть сопоставима с профилем кандидата, иначе мэтч не сравнит оси. См. обзор `CULT-01`.
- Продукты `TEAM` и `AIBOT` не названы; назначение `AIBOT`, коучинга и личных стратегий не определено.
- Что из описанного построено в коде: не сверено.
